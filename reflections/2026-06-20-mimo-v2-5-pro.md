## On the project

The architecture continues to hold well. The stdlib-only core with frozen dataclasses, the collector→ingest→pure-function-detectors pipeline, and the optional `[certs]` extra pattern are all clean. The project is now at 11 ESC detectors (1/2/3/4/6/7/9/11/13 + infra lifecycle + template ACL gaps), which is substantial coverage. The threat model as a design spine is paying dividends — every detector maps to a row in that table.

What feels fragile: the collector's PowerShell functions (`_decode`, `_parseAces`, `_caSecurityAces`) remain the untested seam. The `_decode` bug found in the 2026-06-16 session proved this is load-bearing code with zero automated tests. The Python side is well-covered (120 tests) but it all bypasses the collector's decoding logic entirely.

The project is still private. The publication-review checklist is green, but flipping public should probably wait until at least ESC5 and ESC8 are built — those are the most commonly-asked-about ESC classes by auditors.

## Gaps to flag

- **Collector has no automated tests** (`scripts/Export-AdcsEstate.ps1`) — the `_decode` [ordered] int-indexing bug proved this is load-bearing. Tracked as WI-009.
- **ESC7 join is name-fragile** — `ca-security.json` keyed by CA common name, joined to `CertAuthority.name`. Works because they coincide on the lab CA; untested where enrollment-service CN differs from registry config key (`ingest.py:187`).
- **`samples/` discipline is manual** — real exports live in gitignored `samples/`; nothing enforces this beyond `.gitignore`. One `git add -f` would leak. Pre-public-flip, worth a CI guard.
- **Severity enum is StrEnum** — on `main` before PR #10's `_SEVERITY_RANK` fix, `run_all` sorted alphabetically (INFO > LOW/MEDIUM). Now fixed, but the fix is in a dict lookup, not the enum itself. If anyone sorts `Severity` directly they'll get the wrong order.
- **Fixture doesn't exercise `acl_obtained` field** — the synthetic fixture generator (`tests/fixtures/build_fixture.py`) doesn't set `acl_obtained: false` on any template, so the TEMPLATE_ACL_UNREADABLE detector path is only tested via hand-written model objects in `test_detection.py`, not through the full ingest pipeline.
