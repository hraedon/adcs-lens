## On the project

The architecture continues to pay dividends. Adding four new detectors, a
catalogue, two renderers, and a traceability guard touched only `display.py`,
`detection.py`, `cli.py`, `consequences.py`, `certs.py`, `model.py` — the
frozen-dataclass `Estate` contract and the pure-detector pattern absorbed
everything without a single structural change. The consequences-catalogue-as-
data decision (WI-015) is the keystone: SARIF, HTML, text, and JSON all consume
the same `consequence_for(check)` lookup, so the plain-language prose is defined
exactly once and every output layer is consistent for free. The mechanical
`test_catalogue_matches_every_check_literal_in_detection` AST guard means a new
detector literally cannot ship without its catalogue entry — that is the kind of
invariant that makes a codebase trustworthy to extend.

What strikes me now is that the **value-delivery layer the prior reflection
identified as "essentially absent" is now built**. The non-specialist persona the
charter targets gets: plain-language risk/remediation on every finding, SARIF
for their CI, and a self-contained HTML report an auditor can read and attach.
The deterministic detection core and the narrating/presentation surface are now
both real. The only remaining charter artifact is WI-016 (AI narration) — and
that is genuinely optional.

## On the work done

The single most valuable decision was **not trusting the uncommitted work just
because it was green**. 267 tests passed on arrival, but the adversarial review
(kimi) found four real SHOULD-FIX defects in that "complete" code: an audit
detector that silently dropped CAs with missing `audit_filter` when siblings had
values (a degrade-honesty violation — the project's own hard rule), an audit
critical-bit set that didn't match the documented 127 baseline, a template
weak-key detector that would false-positive on ECDSA, and a traceability test
that could pass for the wrong reason. The second-opinion review (glm) then
caught two more doc/dead-code drifts in my fixes. **Green tests are not
correctness** — the audit degrade gap in particular had unit tests that
*asserted the wrong behavior* (`assert len(findings) == 1` on a path that
should emit two findings). That is the exact failure mode the review process
exists to catch, and it did.

The HTML report (WI-018) is the work I'm most satisfied with and where the review
earned its keep a second time: kimi found that `<header>` was never closed — so
the document was structurally invalid HTML5 (`<main>` nested inside `<header>`,
which the spec forbids). Browsers rendered it fine, so no test would ever flag
it; only a structural parse caught it. I added a `header-closed-before-main`
regression test so it can't regress.

What I'd want a second pair of eyes on: the **audit bit semantics**. I expanded
`_AUDIT_CATEGORIES` to all seven certsvc bits (0x1–0x40 → 0x7F baseline) based
on the reviewer's mapping (0x2=Backup/Restore, 0x40=Store/Retrieve cert). That
mapping is *reasoned from the certsvc documentation*, not measured against a real
CA's AuditFilter output the way ESC8/10/11/13/14 were positive-validated. An
AuditFilter value like 0x7D (missing only 0x2) now surfaces as under-scoped —
correct per the 127-baseline recommendation, but the bit-to-human-name mapping is
unvalidated against a live registry read. The `assert sum(_AUDIT_CATEGORIES) ==
_AUDIT_FULL_BASELINE` invariant at least guarantees the bit set and the baseline
constant can't drift apart.

## Gaps to flag

- **The audit bit→name mapping is reasoned, not measured.** `_AUDIT_CATEGORIES`
  in `src/adcs_lens/detection.py:1349` maps 0x2→Backup/Restore and
  0x40→Store/Retrieve from certsvc docs, never confirmed against a live
  AuditFilter read. A positive live validation (a CA with AuditFilter=0x7D,
  confirming the missing category is named correctly) would close this, mirroring
  how ESC8/10/11/13/14 were positive-validated.
- **The template weak-key detector false-positives on ECDSA templates** (WI-025).
  `detect_weak_key_size` template branch, `detection.py:1446`. Documented honestly
  in the docstring; fix is a collector/model change to capture the template
  CSP/algorithm. Low severity because enterprise CAs default to RSA.
- **HTML determinism holds for `render_html()`, but `print()` to stdout can
  translate `\n`→`\r\n` on Windows** when redirected to a file. Pre-existing for
  all output modes (JSON/SARIF/text too), not HTML-specific. If byte-identical
  HTML attachments across OSes matter, write via `sys.stdout.buffer`. `cli.py:128`.
- **The consequences catalogue and renderers are synthetic-fixture-tested only.**
  The new detectors (weak signing/key, audit) and the HTML report have never run
  against the real gitignored `samples/` export — only the synthetic fixture.
  The samples tests skip in CI. A calibration run against the real export (the
  `-m samples` suite) would confirm the new detectors behave on measured data.
- **ESC15's live positive-validation status is still not explicitly recorded**
  (carried forward from the prior reflection). AGENTS.md records ESC8/10/11/13/14
  as lab-positive-validated; ESC15's own validation isn't stated.
