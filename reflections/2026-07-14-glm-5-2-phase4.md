## On the project

The architecture held up beautifully under the heaviest session yet — four
concurrent subagent implementations touching overlapping concerns (detection,
display, narration, suppression) with zero merge conflicts, thanks to clear
file-boundary instructions. The stdlib-only core, frozen-dataclass contract,
and "degrade honestly" discipline are deeply embedded conventions that every
subagent picked up naturally. The threat-model-as-design-spine approach
continues to pay dividends: the traceability test caught the new OCSP detector
not being mapped to a hygiene row, and the architecture test caught
suppression.py not being in CORE_MODULES.

The one design tension that surfaced: the ESC7 SID-in-SARIF feature (WI-035)
extracts the SID from the detail text in the display layer, which is fragile
(the real detector has the SID directly but doesn't surface it as a structured
field). The adversarial review caught this. The proper fix would be adding a
`metadata` field to the `Finding` dataclass, but that's a model change that
affects the JSON envelope contract — deferred to avoid a schema bump in this
session.

## On the work done

**The live validation was the highest-value work.** Running the v0.6.0 collector
against LABCA immediately revealed that template and PKI-object owner_sids
were empty — the LDAP `SecurityMasks` was set to `'Dacl'` only, not
`'Dacl,Owner'`. The CA owner_sid worked (read from the registry via
`_caSecurityOwner`), but the LDAP-based owner_sid capture was silently broken.
This is exactly the kind of bug that Pester unit tests (which test pure
functions) cannot catch — the `_readOwner` function is correct, but the
SecurityMasks setting that determines whether the owner bytes are returned was
never validated against a live estate. The fix was one line per function, but
discovering it required a live run.

**The adversarial review process caught a critical bug.** The ESC4
property-scoped WriteProperty detector had a false-positive vector: broad Deny
rights (GenericAll, FullControl, GenericWrite) that cover WriteProperty were
not checked in the scoped-WriteProperty Deny-precedence path. The kimi reviewer
found it with a concrete reproduction case. This is the exact scenario where
adversarial review earns its cost — the implementer's tests covered
`WritePropertyAll` Deny but not the broad-right Deny case.

**The orphaned-template detector produced 27 LOW findings on the live estate.**
This is correct — these are default Windows templates (User, EFS, CodeSigning,
etc.) that exist in AD but aren't published by the CA. It's real hygiene
information, but the volume might surprise operators. The suppression feature
(WI-021) is the natural complement: an operator can suppress all
ORPHANED_TEMPLATE findings with a documented risk-acceptance reason and
expiry, so they don't drown out actionable findings.

**The narration layer (WI-016) is deterministic-first, AI-optional.** The
`generate_executive_summary` function produces a structured plain-text summary
using the consequences catalogue — no AI required. The `generate_narrated_summary`
function optionally accepts an LLM client and falls back to the deterministic
summary on any error. This is the right design: the tool is useful
out-of-the-box, and the AI layer is additive, never load-bearing.

## On what remains

1. **PyPI publishing requires a PyPI API token.** The workflow
   (`.github/workflows/publish.yml`) is ready and the package builds cleanly,
   but `PYPI_API_TOKEN` must be configured as a GitHub secret. Until then,
   install-from-git remains the primary path.
2. **The ESC7 SID-in-SARIF feature is fragile** (extracts SID from detail text
   in the display layer). A future model change to add a structured `metadata`
   field to `Finding` would be the proper fix.
3. **The `_finding_with_consequence` function is duplicated** between
   `display.py` and `narration.py`. Should be extracted to a shared helper.
4. **The collector doesn't capture DER cert/CRL files.** The OCSP/CDP/AIA
   detectors only fire when the `[certs]` extra is installed AND the export
   contains DER files. Currently the collector always adds `'certs'` to
   `skipped_passes`. A future collector enhancement to export CA cert/CRL DERs
   would activate these new detectors on real estates.
5. **The SARIF `locations` structure was fixed** — `artifactLocation` and
   `logicalLocations` are now correctly nested inside `locations[]` per the
   SARIF 2.1.0 spec, and the URI scheme uses `file:///adcs-lens/` for GitHub
   Code Scanning compatibility. A schema-validation test with a vendored
   SARIF fixture guards against regressions.

## Gaps to flag

- **The collector's AuditFilter is null on LABCA** — the registry key
  `CA\AuditFilter` doesn't exist. The detector correctly degrades to
  `CA_AUDIT_NOT_EVALUATED`, but this means audit configuration is never
  checked on this estate. Not a code bug — a real estate condition.
- **The ESC10 enforcement is UNKNOWN on all 3 DCs** — the
  `StrongCertificateBindingEnforcement` registry value is not set. The
  detector correctly reports `ESC10_ENFORCEMENT_UNKNOWN` (INFO). Setting it
  to 2 (Full) explicitly would resolve the ambiguity.
- **The `apply_suppressions` function's date-only expiry uses start-of-day
  UTC** — an operator writing `"expires": "2026-12-31"` means the suppression
  expires at midnight UTC on Dec 31, not end-of-day. This is documented in
  the code but could surprise operators. Consider using end-of-day.
- **The narration module's `_LlmClient` Protocol** is defined but no
  concrete LLM client implementation exists yet. The `--narrate` flag uses
  the deterministic mode (no LLM). An LLM client would need to be passed
  programmatically — there's no CLI flag for it yet.
- **440 tests, 0 failures, but the Pester collector tests were not re-run
  on this machine** (they run on Windows in CI). The scoped-WriteProperty
  collector change (`WriteProperty:<guid>`) has a Pester test, but it was
  only verified via the live collector run, not via the Pester suite locally.
