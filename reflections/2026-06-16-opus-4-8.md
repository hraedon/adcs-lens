# Session Reflection — 2026-06-16

**Work summary:** Took adcs-lens from one detector (ESC6) to a full
template-escalation + CA-rights suite (ESC1/2/3/4/6/7/9 + infra expiry), built
the collector's Phase 1b passes (template DACLs + `CA\Security`), scrubbed the
git history of real lab identifiers (filter-repo + repo recreate), and validated
every detector end-to-end against the live CA `ad-LABCA01`. 8 PRs, 83 tests, CI
green throughout. An independent opencode/GLM review at the end caught a real
false-negative gap (now fixed) and seeded `docs/review-findings.md`.

---

## On the project

The architecture holds up well under growth. The stdlib-only deterministic core
with the optional `[certs]` extra, the frozen normalized model, and the
"collector emits JSON → ingest → pure-function detectors" split meant adding five
detectors was almost mechanical — each is a small pure function over the same
`Estate`, and the `_low_priv_enrollers` / degradation helpers composed cleanly.
The architecture guard (stdlib-only truth path) is a genuinely good idea and
caught nothing only because the discipline held.

The one structural weakness this session exposed is the **collector/ingest
boundary is the untested seam**. Everything Python is well-covered, but the
PowerShell collector has no test harness, and the unit tests feed hand-written
JSON that bypasses the collector's decoding entirely. That's exactly where the
real bug lived (see below). The model is also slightly lossy at that boundary —
ACEs drop the `ObjectType` GUID for non-ExtendedRight rights, which is what
limits ESC4.

## On the work done

The detectors I'm confident in — they're faithful to the SpecterOps ESC
definitions, each has a degradation path, and (the part I'm most glad about) I
validated them against a *real* CA rather than just fixtures. The decision to use
the homelab as a real lab paid off concretely: creating an actual ESC1-vulnerable
template surfaced the `_decode` `[ordered]`-int-indexing bug that all 70+ unit
tests and even the read-only real runs had missed (the real runs were *false
negatives* — they reported clean because the flags were mis-decoded). That's the
single most valuable thing that happened this session, and it only happened
because I could write to the CA.

Less sure about: ESC severity choices are judgment calls (ESC2/ESC3 as HIGH, ESC7
ManageCA as CRITICAL) — defensible but not authoritative. And I leaned toward
flagging unpublished templates (latent risk) over suppressing them; a real
operator might find that noisy.

## On what remains

Needed before a complete ESC story:
1. **ESC4 blanket-WriteProperty** (`docs/review-findings.md`, HIGH) — needs the
   collector to preserve whether WriteProperty is object-wide vs property-scoped,
   a model field for it, then the detector. Validate by granting a test template
   blanket WriteProperty to Domain Users.
2. **pki-acls collection pass → ESC5** (NTAuth/AIA/CDP/container DACLs). The
   `_parseAces` machinery already exists; it's mostly wiring + lab validation.
3. **ESC11** (interface_flags `IF_ENFORCEENCRYPTICERTREQUEST` *absent*) and
   **ESC13** (template `issuance_policy_oids` → OID `group_link_sid` join) — both
   cheap, no new collection.

Nice to have: ESC15, and a per-template "ACL unreadable" signal.

## Gaps to flag

- **The collector has no automated test.** `scripts/Export-AdcsEstate.ps1` is
  validated only by running it against the lab. The `_decode` bug proves this is
  load-bearing. A Pester test (or a pure-PowerShell unit harness for `_decode` /
  `_parseAces` / `_caSecurityAces`) would have caught it. Highest-value gap.
- **ESC4 false negative** — blanket WriteProperty unflagged (`detection.py`
  `_DANGEROUS_TEMPLATE_CONTROL`). Tracked, but it's a real miss, not cosmetic.
- **No per-template unreadable-DACL signal** — a template whose DACL came back
  empty is indistinguishable from a safe one (`detection.py` ESC1/2/3/4 loops).
- **ESC7 join is name-fragile** — `ca-security.json` is keyed by the CA common
  name and joined to `CertAuthority.name`; works because they coincide on this CA
  (`ad-LABCA01`), untested where the enrollment-service CN differs from the
  registry config key.
- **`samples/` discipline is manual** — real exports (with real SIDs/CA/domain)
  live in gitignored `samples/`; nothing enforces that beyond `.gitignore` + my
  own checks. One careless `git add -f` would leak. Pre-public-flip, worth a CI
  guard that greps committed files for the internal-identifier patterns.
